# ESP32 voice entry audit — 2026-11-04

> Publication note: this is the committed copy. The local serial port, device MAC
> suffix, LAN address and the private archive path are redacted so the document
> can live in a public repository; the unredacted original stayed local.

## Scope and hardware

- Project: local Python WebSocket/OTA service plus `xiaozhi-esp32` firmware.
- Connected board: ESP32-S3 revision 0.2, 8 MB PSRAM, USB Serial/JTAG on
  `/dev/cu.usbmodem<serial>` (device MAC suffix omitted). The other USB modem
  port was not used.
- Baseline: service repo `9f56cfa`, firmware repo `f7ef573b`. The full 16 MB
  board flash was backed up before modification to a private archive at
  `$HOME/AI_Workspace/02_Archive/esp32-voice-firmware/audit-20261104/board-before.bin`
  (SHA-256 `70d35e3144baea78e80ac5c5164071aa96ef91e2f02217d8b05e1aeac102f9ed`).
  The backup is private because it contains Wi-Fi settings and other NVS data.

## Findings and work completed

| Priority | Finding | Evidence | Action |
| --- | --- | --- | --- |
| Critical | Port 4410 accepted an unauthenticated WebSocket client. The session sent MCP initialize, including a vision bearer token that was also the control token. | A synthetic LAN client obtained the capability without a device secret. | Added a persistent device pairing token, WebSocket bearer check, and private firmware pairing. Anonymous OTA no longer returns a WebSocket token. |
| High | The old macOS launch wrapper orphaned its Python child during `launchctl kickstart -k`; the replacement then collided on ports 4410/4411. | Live process and port inspection showed a duplicate server and restart loop. | LaunchAgent now invokes `scripts/run_service.sh`, which `exec`s Python. Restart produced one managed server process. |
| Medium | The device had no remotely callable equivalent of the BOOT wake action. A USB DTR pulse did not invoke the physical button handler. | Live DTR test failed to start a conversation. | Added an authenticated one-shot `/debug/wake` command, delivered via the existing mute poll and acknowledged by the board. The board invokes `ToggleChatState()` only while unmuted and idle. |
| Medium | One proactive test depended on wall-clock time and failed around midnight. | `test_status_after_a_dry_run_trigger` failed at the real date boundary. | Injected a fixed clock into that test. |
| Medium | `scripts/build.py` did not expand its OTA base variable on the normal build path. | Code path inspection. | Expanded the base consistently and used a non-routable public placeholder when no base is supplied. |
| Low | A paired client closing before `hello` produced a server traceback and left a session registered. | Live WebSocket probe after pairing. | Moved handshake under the connection cleanup block and handled normal close. |
| High | WebSocket v2/v3 audio parsing trusted the packet's declared length, allowing a short or malformed frame to read beyond its buffer. | The receive callback cast `data` to an audio header and copied `payload_size` bytes without comparing it to `len`. | Validate header, type, version and exact payload length before copying; parse fields without writing into the receive buffer. |
| Medium | A remote wake ignored while the device was busy was still acknowledged and lost. | The controller recorded the wake ID before the main task checked device state. | Acknowledge only after the main task accepts the wake; busy requests remain pending and retry when idle. Verified on the board. |
| Medium | Boot-time mute sync failed open when the endpoint was known but the server had not yet confirmed an unmuted state. | The initial `muted` value was false and `HandleMuteStateChanged` only held audio for `status.muted`. | Hold capture/uplink until a known endpoint reports a synced, unmuted state. A new board without an endpoint can still make its first pairing connection. |
| Medium | OTA added the timezone offset to Unix epoch before `settimeofday`, making the system clock eight hours fast for this server. | Local OTA sends a UTC millisecond timestamp plus `timezone_offset=480`; firmware added both. | Set UTC epoch directly and configure POSIX `TZ` for the display's local time. |

## Validation

- `pytest -q` passed after the service changes; both repos passed `git diff --check`.
- Final audited app binary: 2,867,104 bytes, SHA-256
  `f373f7f741b70edfee6d85ec213a93a9bdc7d6371b9efcf8a9aac17bc49e799f`.
  App-only flash at `0x20000` completed with esptool verification; NVS and Wi-Fi
  were preserved. The paired image is stored privately as `audited-app-final.bin`
  in the archive above. The previously flashed pairing image was independently
  verified against the board with `esptool verify-flash` before these fixes.
- Anonymous and incorrect-token WebSocket connections closed with code `1008`;
  the paired token connected. The board then connected from a private LAN
  address, completed `hello` and MCP initialize, and started listening after a
  remote wake. The wake ID was acknowledged on the next poll. The mute state was
  false.
- A test NVS image containing a pairing token was generated with the ESP-IDF
  Python environment; both the binary and optional CSV had mode `0600`.
- Firmware host suite: 143 tests passed (3 skipped). The updated ESP32-S3 app
  built from the cached Ninja graph. Live test confirmed that a wake sent during
  realtime listening stayed pending without an ACK; after muting, returning to
  idle, and unmuting, the same wake was executed and acknowledged.

## Remaining risks and next upgrades

1. **Protect traffic in transit.** OTA still uses HTTP and audio/control traffic
   uses WS on the local network. A network adversary can observe the embedded
   device token or tamper with OTA responses. Move to HTTPS/WSS with certificate
   validation and a practical certificate rotation plan before using untrusted
   networks.
2. **Protect firmware and stored secrets.** Secure Boot and Flash Encryption are
   disabled; physical flash access can reveal the paired token and Wi-Fi data.
   Enable these only after validating recovery, OTA signing, and the effect on
   USB Serial/JTAG, because eFuse changes are irreversible.
3. **Constrain anonymous media ingress.** `/debug/upload` remains anonymous for
   firmware compatibility and accepts up to 8 MB per request. Add a device
   capability or separate upload token, rate limits, and disk quotas. Media GET
   routes are anonymous and should use short-lived opaque names or authorization.
4. **Harden provisioning.** The fallback `Xiaozhi-XXXX` SoftAP is open. Add a
   per-device pairing code or another authenticated provisioning path.
5. **Build reproducibility.** The ESP-IDF component manager stalled during a
   network dependency refresh. The paired binary was built from the existing
   cache after updating the generated config header, with CMake regeneration
   temporarily disabled and then restored. The source Kconfig and `sdkconfig`
   contain the same pairing value, but a clean `idf.py build` still needs to be
   run after the registry connection is repaired.

The current result is a working, remotely wakeable, paired local device. It is
not yet suitable for a hostile network or unattended public deployment.

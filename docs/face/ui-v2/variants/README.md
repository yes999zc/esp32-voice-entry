## 2. 逐版说明

### A｜日志优先（推荐默认）

- 布局：顶栏 40（`■ 小智 在线` / 时间 / WiFi / 音量）→ 左窄条 64（3 组：状态 在听、内存 33KB、帧 1024）→ 日志 7 行（x72–472，14px / 行高 27）→ 底栏字幕。数值格式与 B/D 卡片一致。
- 取舍：**日志是主角**，横向 400 px 能放下 `first frame 420ms`（17 字符）；左侧窄条只留最常看的 3 个数，不抢空间。
- 适合：日常使用 + 想知道"刚才那句话为什么慢"；一句话说完，字幕条和日志能同时看。
- 风险：窄条 12px 中文标签在 480×320 上偏小（真机需确认）；日志 7 行意味着更早的条目要等滚动。

### B｜左仪表 + 右日志

- 布局：顶栏 32（只留 `小智 在线`/时间/WiFi，**音量不重复**，在卡片里）→ 左 168 px（35%）6 张 76×64 卡片（2×3）→ 右日志 7 行（296 px，14px / 行高 28）→ 底栏字幕。
- 取舍：**一眼看状态**（在听/音量/网络/内存/帧数），日志退到 60% 宽；代价是每行只能放 ~20 字符，长消息截断更早。
- 适合：更关心"设备现在健康吗"而不是逐条读日志；调试网络/内存问题时看卡片最快。
- 风险：卡片 12px 标签 + 296 px 日志宽度；`get_weather 0.8s` 之类刚好放得下，再长就 `…`。

### C｜全屏终端 + 浮层

- 布局：无实心顶栏，11 行日志缓冲铺满（14px / 行高 22），顶部 30 px 半透明状态带（`小智 在线` / 时间 / WiFi / 音量），底部 50 px 字幕浮层；最新行从下往上滚，**可见 10 行（18:58:57–18:59:06）**，**最早 1 行缓冲被顶带遮住**（18:58:56）。
- 取舍：**信息量最大**，最像"看日志"；代价是没有指标卡，顶带会遮住最早 1 行；最新行必须停在字幕上方（本样张的告警行 `18:59:06 sram 33KB low` 就在字幕上方）。
- 适合：调试模式 / 现场排障（长按或设置页切进来），不适合长期当主界面。
- 风险：14px + 22 行高偏挤；浮层遮挡需要明确"最新行永远在字幕上方"的滚动规则；半透明叠加在 LVGL 上要额外混合开销。

### D｜上仪表 + 下日志（可选）

- 布局：顶栏 30（**音量不重复**，在卡片里）→ 6 张 152×60 卡片（3×2，占 30–166）→ 日志 4 行（13px / 行高 20）→ 底栏字幕。
- 取舍：仪表和日志各占一半，**两头都想要但两头都不够**：4 行日志只能看到最近 4 条，13px 是四版里最小的字。
- 适合：只关心"最近发生了什么 + 当前指标"的轻量场景；也可做成"上下区可切换"（同区域轮换指标/日志）。
- 风险：**13px 等宽在 480×320 上可读性最差**，建议不低于 14px；若坚持双区，建议把日志压到 3 行、字号回 14。

## 3. 推荐

**推荐 A 作为默认主界面**，理由：

1. 9哥 的核心诉求是"看到实时日志"，A 给了 **7 行 × 400 px** 的有效日志区，是四版里"行数 × 每行宽度"最均衡的；
2. 左侧 64 px 窄条保住了最关键的 3 项（状态/内存/帧），音量在顶栏，不牺牲主信息；
3. 字幕条保持现状（60 px 固定底栏），不做浮层，**改动面最小、风险最低**；
4. B 的 6 卡片适合"健康检查"，可做成 A 的一键切换视图；C 适合做调试模式；D 不建议做默认。

组合建议：**A 默认 + B 备选（设置页切换）+ C 调试模式**；三套共用同一套日志渲染器与字体，只是布局不同。

## 5. 重跑与实现备注

```sh
python3 docs/face/ui-v2/variants/render_variants.py   # 需 macOS 系统字体
```

- 日志渲染器是纯绘制原型；Phase B 若落地，建议在 LVGL 里用 `lv_label` 单行 × N + 环形缓冲，14px 等宽用 JetBrains Mono 子集，中文消息用 MiSans 14（两段文本拼接或独立 label）。
- 滚动策略建议：新行入队 → 整体上移 22/27 px（`lv_anim` 120 ms）→ 旧行回收；不要整屏重绘。
- 性能：一行 14px 文本 ≈ 30 字符 × 14×8 px 区域，脏矩形约 400×27；按现有 SPI 带宽（5 MB/s）单行 <2 ms，10 行/秒的刷新压力可忽略（最终以真机实测为准）。
